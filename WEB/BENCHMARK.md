# 로컬 서버 기준 측정 · 2026-09-07

Jetson 실제 USB 카메라, V4L2, 640×480, 장치 설정 30 FPS. 각 모드에서 3초 준비 후 10초간 서버 출력 순번 증가량을 측정했습니다. JPEG 품질 80. 얼굴 검출 수 0명, 팬틸트 추적 OFF.

| 모드 | 완료 프레임 | 측정 시간 | 서버 FPS | 평균 JPEG 처리 |
| --- | ---: | ---: | ---: | ---: |
| 카메라만 | 301 | 10.017초 | 30.05 | 해당 없음 |
| 카메라 + JPEG | 300 | 10.017초 | 29.95 | 5.43ms |
| AI + JPEG | 300 | 10.016초 | 29.95 | 2.75ms |

해당 장면에서는 약 30 FPS를 유지했습니다. JPEG 평균 크기는 약 23.4 KB입니다. 짧은 측정과 카메라 프레임 경계 때문에 30 FPS보다 약간 높거나 낮게 나올 수 있습니다. 모드 간 JPEG 시간 차이는 이 결과만으로 원인을 판단할 수 없습니다.

**Wi-Fi 수신 측정은 아직 아닙니다.** 전송 클라이언트 없이 서버 파이프라인만 측정했습니다. 얼굴이 없어 SFace 특징 추출 부하도 측정되지 않았습니다. 실제 얼굴이 있는 장면과 별도 Wi-Fi 기기의 브라우저에서 30초 수신 측정이 필요합니다.

재현: `AI/.venv/bin/python WEB/tools/benchmark_local.py --url http://127.0.0.1:8001`. 이 명령은 카메라를 모드별로 재시작하며 마지막에 추적 OFF인 AI 모드로 복귀합니다.

## WebRTC 이식

이후 실시간 화면을 H.264 WebRTC로 변경했습니다. 원본/AI 표시 선택, `<video>` 재생, WebRTC 통계 기반 30초 측정을 제공합니다. 기존 무선 JPEG 보고서의 실제 서버 기록은 30.845초 / 표시 770장 / 24.9635 FPS / 출력 건너뜀 155장 / 요청→그리기 39.7701ms였습니다.

새 경로는 합성 프레임을 사용한 실제 로컬 ICE/DTLS/H.264 송수신 테스트를 통과했습니다. 이 테스트는 성능 벤치마크가 아닙니다. 브라우저 자동 검증 실행은 승인되지 않아 수행하지 않았으며, WebRTC의 실제 브라우저·Wi-Fi FPS는 아직 측정하지 않았습니다. 새 화면의 30초 측정으로 같은 조건에서 다시 비교해야 합니다.

WebRTC 실제 무선 시험에서 약 2초 영상 지연과 수 초 RTT가 발생해 실시간 경로에서 제거했습니다.

## 최신 프레임 AI 구조 · 2026-09-07

카메라 캡처와 AI 처리를 분리하고, AI가 늦으면 중간 프레임을 폐기하도록 변경했습니다. 실제 USB 카메라 640×480, 얼굴 없는 장면, 로컬 HTTP 클라이언트 10초 측정 결과는 캡처 30.0 FPS, AI 약 30 FPS, 클라이언트 30.16 FPS, 처리 23.94ms, 프레임 나이 24.19ms였습니다. 측정 중 AI가 건너뛴 카메라 프레임은 0장이었습니다. 급격한 장면 변화와 Wi-Fi 결과는 별도 측정이 필요합니다.
