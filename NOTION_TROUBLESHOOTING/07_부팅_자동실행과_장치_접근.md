# Jetson 부팅 자동 실행과 카메라·UART 장치 접근

## 자동 실행 구조

통합 웹 서버는 시스템 서비스 `vision-tracker-web.service`로 실행한다.

- 부팅 시 자동 시작
- 네트워크 준비 이후 실행
- 서버 오류 종료 시 3초 후 재시작
- 웹 서버 시작과 함께 카메라 자동 시작
- 포트 8000에서 모든 네트워크 인터페이스의 요청 수신
- Uvicorn 접근 로그 비활성화

카메라 자동 시작은 다음 환경 변수로 설정된다.

```text
VISION_AUTOSTART_CAMERA=1
```

## 주요 명령

```bash
sudo systemctl restart vision-tracker-web.service
sudo systemctl status vision-tracker-web.service
journalctl -u vision-tracker-web.service --no-pager -n 100
```

Python·설정·API 등 서버 코드를 변경하면 서비스를 재시작해야 한다. 브라우저의 정적 JavaScript나 CSS만 변경한 경우에는 일반적으로 브라우저 새로고침으로 반영된다.

## 카메라와 UART 접근

서비스의 `PrivateDevices=false` 설정으로 `/dev/video*`와 `/dev/ttyACM*` 접근을 허용한다. 서비스를 실행하는 사용자는 일반적으로 다음 그룹에 포함되어야 한다.

- 카메라: `video`
- USB UART: `dialout`

확인 명령:

```bash
id
ls -l /dev/video*
ls -l /dev/ttyACM*
```

사용자를 그룹에 추가한 경우 재로그인하거나 재부팅해야 그룹 변경이 실제 서비스에 반영된다.

```bash
sudo usermod -aG video,dialout aidl
```

## 권한 오류와 장치 미인식 구분

`/dev/video0`이 존재하지만 접근이 거부되면 사용자 그룹이나 서비스 격리 설정 문제일 가능성이 높다.

반대로 `ls /dev/video*` 결과가 `No such file or directory`이면 권한 문제가 아니다. 커널이 카메라 장치를 만들지 못한 상태이므로 다음을 확인한다.

```bash
lsusb
lsmod | rg 'uvcvideo|videodev'
journalctl -k --no-pager | tail -n 100
```

이 경우 USB 케이블·전원·포트·카메라 인식 또는 `uvcvideo` 드라이버 문제를 먼저 해결해야 한다.

## 카메라 중복 점유

이전 PyQt 서비스나 별도 테스트 프로그램이 카메라를 열고 있으면 통합 웹 서버가 카메라를 열지 못한다. 카메라를 사용하는 프로그램은 한 번에 하나만 실행한다.

```bash
fuser /dev/video0
```

자동 실행 설치 스크립트는 이전 데스크톱 카메라 서비스를 비활성화한 뒤 통합 웹 서비스를 등록한다.
