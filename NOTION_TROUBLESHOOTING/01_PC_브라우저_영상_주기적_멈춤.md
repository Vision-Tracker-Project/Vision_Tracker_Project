# PC 브라우저 영상이 1~2초씩 주기적으로 멈춘 문제

## 증상

- Jetson 카메라와 AI 처리는 계속 실행되는데 PC Chrome과 Whale 화면이 간헐적으로 1~2초 정지했다.
- 정지 후에는 오래된 영상을 순서대로 보여주지 않고 최신 화면으로 바로 복귀했다.
- Whale에서 가장 심했고 Chrome에서는 빈도가 낮았다.
- 같은 서버에 접속한 iPhone Safari에서는 끊김이 없었다.
- 5GHz Wi-Fi와 Jetson USB 네트워크(`192.168.55.1`)에서도 PC 브라우저의 증상이 남았다.

## 원인 규명

Chrome DevTools에서 HAR와 Performance Trace를 수집해 분석했다.

- 영상 요청: 2,330건
- 1초 이상 지연된 영상 요청: 26건
- 프록시 결정 단계에서 1초 이상 지연된 요청: 25건
- 프록시 단계 지연: 약 1.77~2.42초
- 지연된 요청의 실제 Jetson 응답 대기: 최대 약 29ms
- 이미지 디코딩: 최대 약 7ms

서버가 영상을 늦게 만든 것이 아니라, Windows 브라우저가 요청을 보내기 전에 프록시 사용 여부를 결정하면서 기다리고 있었다.

프록시는 PC의 요청을 대신 전달하는 중계 서버다. Windows의 자동 프록시 검색(WPAD)이나 자동 설정 스크립트(PAC)가 켜져 있으면 브라우저가 각 연결에서 직접 접속할지 프록시를 사용할지 판단한다. 이 과정이 실패하거나 늦어지면서 약 2초의 공백이 생겼다.

## 해결

Windows에서 다음 설정을 변경했다.

1. `설정 → 네트워크 및 인터넷 → 프록시`로 이동한다.
2. `자동으로 설정 검색`을 끈다.
3. 사용하지 않는 `설정 스크립트 사용`과 `프록시 서버 사용`도 꺼져 있는지 확인한다.
4. Chrome과 Whale을 완전히 종료한 뒤 다시 실행한다.

이 설정을 해제한 뒤 주기적인 1~2초 정지가 해결됐다.

## 판단 기준

영상이 멈출 때 Jetson의 프레임 번호가 계속 증가하고 iPhone Safari가 정상이라면 카메라나 AI보다 PC 브라우저의 네트워크 설정을 먼저 확인한다.

HAR의 요청 Timing에서 다음 항목을 확인한다.

- `_blocked_proxy`: 프록시 결정에 사용된 시간
- `wait`: 요청 전송 후 서버 응답을 기다린 시간
- `receive`: 응답 데이터를 실제로 수신한 시간

`_blocked_proxy`만 수 초이고 `wait`가 수십 ms라면 Jetson 서버 문제가 아니다.
